# CRM Finance

Telegram Mini App для бухгалтерских услуг: налоговая отчётность и консультации
для ИП, самозанятых и ООО — резидентов РФ. AI-консультант отвечает на типовые
вопросы, сложные случаи передаются живому бухгалтеру.

## Структура проекта

```
CRM Finance/
├── frontend/          — Telegram Mini App (то, что видит пользователь)
│   └── index.html
├── backend/           — API-сервер и база данных
│   ├── src/
│   │   ├── index.js         — точка входа сервера
│   │   ├── routes/          — обработчики запросов (клиенты, бухгалтеры, чат, 1С)
│   │   └── db/
│   │       ├── schema.sql   — структура базы данных
│   │       └── pool.js      — подключение к PostgreSQL
│   ├── package.json
│   └── .env.example         — пример настроек (скопируйте в .env)
└── README.md          — этот файл
```

## Как всё это работает вместе

1. **frontend/index.html** — то, что открывается в Telegram по кнопке меню бота.
   Сейчас это статичный прототип (заполнен реальными данными для примера, ничего
   не сохраняется). Именно этот файл вы заливаете на Vercel.

2. **backend/** — сервер, который со временем начнёт принимать данные из
   формы регистрации, вести чат с AI, хранить заявки к бухгалтерам. Пока что
   frontend с ним не связан — это следующий шаг.

3. **backend/src/db/schema.sql** — описание таблиц базы данных: клиенты,
   бухгалтеры, заявки, сообщения чата. Отражает то, что обсуждалось при
   проектировании: тип клиента (ИП/самозанятый/ООО), ИНН, налоговый режим,
   интеграция с 1С и т.д.

## Быстрый старт backend (для разработчика)

```bash
cd backend
npm install
cp .env.example .env
# заполните .env реальными значениями (адрес базы данных и т.п.)
npm run dev
```

Сервер поднимется на `http://localhost:3000`. Проверить, что он жив:
`http://localhost:3000/health` должен вернуть `{"status":"ok"}`.

## Деплой

- **Frontend** → Vercel (см. инструкцию в истории чата — загрузка через GitHub).
- **Backend** → потребует отдельный хостинг с поддержкой Node.js и PostgreSQL
  (например Railway, Render, или VPS) — это следующий этап, когда понадобится
  реальное сохранение данных.
